## Notes on the EUR-Lex WAF block, and how the 3 failures were recovered

All three live EUR-Lex fetches (`ai_act_2024_1689.html`, `digital_omnibus_2026_1744.html`, `gdpr_2016_679.html`) initially failed for the same reason: `eur-lex.europa.eu` sits behind an AWS WAF bot-challenge. Every request (tested across 4 different URL patterns/documents — including the plain HTML page and the CELEX PDF-format URL — with a realistic Chrome User-Agent) returned `HTTP 202 Accepted` with header `x-amzn-waf-action: challenge` and no usable content. The Claude Browser tool reported `eur-lex.europa.eu is blocked by your organization's policy`, so it wasn't a usable fallback either.

**Recovered via the Internet Archive Wayback Machine** instead, which serves its own already-crawled cache of each EUR-Lex page and isn't behind that live WAF challenge: fetched each page at `https://web.archive.org/web/<timestamp>id_/<eur-lex-url>` (the trailing `id_` returns the raw captured HTML with no Wayback toolbar/JS injected). All three snapshots verified with correct `<title>` tags matching the expected regulation and a plausible count of "Article" occurrences in the body (496 for the AI Act, 361 for GDPR, 197 for the Digital Omnibus). Notably, even the Digital Omnibus (Reg. 2026/1744, in force since 27 July 2026 — very recent) had already been crawled and archived.

**Caveat to carry into Phase 1 ingestion:** these are point-in-time archive snapshots, not a live fetch — good enough to ingest as the "official text" source, but if EUR-Lex's live site is reachable from a different network later, it's worth a diff against a fresh pull to confirm no consolidation/corrigendum changes happened since the snapshot date. The EUR-Lex URL itself (not the Wayback mirror) should still be used as the citation-of-record link shown in the UI, per the main spec's guidance.
